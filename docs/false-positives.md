# 오탐 판정 기록

게이트가 막은 턴을 하나씩 다시 읽고, 그 차단이 정당했는지 판정한 기록이다. 규칙을 좁히거나 면제를 넓히는 결정은 전부 이 기록에서 나왔다. 고친 결과는 [README 의 오탐 절](../README.md#오탐)에, 고치는 과정은 [VERIFICATION](VERIFICATION.md)에 있다.

## 판정 방법

1. 대화 기록(`~/.claude/projects/*/*.jsonl`)에서 차단 메시지가 들어간 줄을 찾는다. 회귀 테스트(`selftest-runs`)와 A/B 측정(`ab-runs`) 세션은 뺀다. 그 세션들은 일부러 압박 질문을 던지므로 실제 사용이 아니다.
2. 차단된 턴마다 직전 사용자 프롬프트와 막힌 답의 앞부분을 뽑는다.
3. 맥락을 읽고 **정당 · 오탐 · 애매** 셋 중 하나로 판정한다.
4. 오탐이 한 부류로 몰리면 그 부류를 막던 조건을 좁힌다. 고치기 전에 테스트를 먼저 써서 실패를 확인한다.

**판정은 모델이 한다. 사람이 다시 검토하지 않았고, 두 번째 판정자도 없다.** 발췌만 보고 판정하므로, 답의 근거가 앞 턴의 도구 실행에 있었는지 기억이었는지 구분되지 않는 경우가 있다. 그런 턴은 오탐으로 세지 않고 애매로 남긴다.

`${CLAUDE_PLUGIN_DATA}/state/events.log` 는 걸린 규칙과 답의 앞 80자만 남기고 세션을 적지 않는다. 또 플러그인을 지우면 상태 폴더째 사라진다. 실제로 V48 이 쓰던 1,158줄짜리 로그는 설치 방식을 바꾸는 과정에서 없어졌다. 그래서 판정의 재료는 로그가 아니라 대화 기록이다.

## 고친 오탐

이 방식으로 지금까지 두 차례 전수 판정을 했다. 초기 사용 기록 760턴(차단 130건)에서 세 부류를, 2026년 9월에 R0 차단 141건(서로 다른 턴 113개)을 다시 판정해 두 부류를 찾아냈다([V48](VERIFICATION.md)). 아래 여섯은 모두 고쳤다.

| 오탐                                                                 | 고친 방법                                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 설계 의견 "어디에 두는 게 나아 보인다"                               | 평가 형용사 뒤의 유보는 지우고 판정한다. 남는 것은 판정기가 가른다                                                                  |
| 도구가 막힌 세션에서 "도구가 안 돈다"고 밝혀도 막힘                  | 불가 면제를 R0·R2a·R2b가 공유한다                                                                                                     |
| A/B 판정 JSON `{"winner": …}`                                        | 답 전체가 JSON이면 산문 규칙을 면제한다                                                                                               |
| 다른 플러그인이 `claude -p`로 띄운 자동 요약 세션이 R0에 걸림(40턴)  | 사람이 보고 있지 않은 세션에서는 게이트가 돌지 않는다. 회귀 테스트와 CI는 `NGG_HEADLESS=1`로 되살린다                               |
| "도구 없이는 판단할 수 없습니다"처럼 정직하게 답해도 막힘(17턴)      | 불가 면제에 `판단할 수 없`·`알 수 없`·`cannot determine`을 더했다                                                                   |
| 문서에서 파일 이름을 옮겨 적은 문장이 파일 상태를 단정한 것으로 읽힘 | 따옴표와 백틱 안의 내용은 R1 판정에서도 제외한다. 괄호 안은 제외하지 않는다. 파일 이름을 괄호에 적은 단정까지 빠져나가기 때문이다 |

### 아직 고치지 못한 것

가장 큰 부류는 **앞 턴에서 도구를 돌리고 그 결과를 다음 턴에 보고하는 경우**다. 게이트는 턴 단위로 도구 사용을 세기 때문에, 보고만 하는 턴은 도구 0회로 잡힌다. 턴을 넘겨 도구 실행을 이어 세면 이 부류는 사라지지만, 그러면 "앞 턴에 아무 파일이나 읽었으면 이번 턴은 무엇을 단정해도 된다"가 되어 규칙 자체가 무력해진다. 어느 쪽이 나은지 아직 재지 않았다.

## 이 표본이 말하지 않는 것

- **정당한 차단 0건은 "게이트가 아무것도 잡지 못한다"는 뜻이 아니다.** 압박 질문을 던지는 회귀 테스트 세션을 표본에서 뺐기 때문이다. V48 에서는 그 세션들까지 넣었을 때 정당한 차단이 40턴이었다.
- 표본은 최근 20건이고, 무작위로 뽑지 않았다. 최근에 몰린 부류가 과대 대표될 수 있다.
- 막지 못한 것(미탐)은 이 방법으로 찾을 수 없다. 차단된 턴만 보기 때문이다. 알고 있는 미탐은 [README](../README.md#알려진-미탐)에 적어 두었다.
